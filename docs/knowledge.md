# 本地知识库

所有工作区和会话共用一个本地知识库，不维护分类。侧栏“知识库”只读展示“父目录 → 原文件路径”，支持刷新；界面没有上传、导入、分类或删除操作。智能体通过工具导入和搜索，沿用当前会话的权限模式及工具确认/结果事件。

导入只读取用户提供的原路径，不复制、上传或改写原文档。应用仅保存正文片段、检索索引和文档元数据，文档解析与正文检索均在本地完成。

## 目录范围与全局搜索

使用 `KnowledgeSearch` 对正文片段进行 BM25 关键词与稠密向量混合检索，用 RRF 融合两路排名，既支持自然语言问题，也支持中英文关键词。可通过 `parent_paths` 限定一个或多个目录范围，省略目录范围时搜索全库。需要确认文件路径时，使用 `KnowledgeList` 浏览目录或按文件名筛选。用户明确指定目录时保留其范围，不擅自扩大。

正文搜索仅接受 `parent_paths` 目录列表，不支持文件名或指定文件列表筛选。多个目录及其子目录取并集，重复目录和父子目录重叠按文件路径去重，不同路径的相同内容分别返回。目录按路径边界匹配，例如 `docs/` 不包含同级的 `docs-old/`。显式 `parent_paths: []` 表示空范围；省略或传 `null` 才是全局搜索。每个片段的 `source` 是当前范围内的原文件路径。

## 工具

| 工具 | 作用 | 参数 |
| --- | --- | --- |
| `KnowledgeImport` | 按原文件路径入库，修改时间未变时跳过，变化时更新 | `file_path` |
| `KnowledgeSearch` | 多个目录范围或全局混合搜索正文，返回带来源的片段 | `query`，可选 `parent_paths`（最多 100 个目录）、`top_k`（默认 5，最多 20） |
| `KnowledgeList` | 分页查看已入库文件路径及元数据 | 可选 `parent_path`、`filename`、`offset`（默认 0）、`limit`（默认 50，最多 100） |

工具传入的相对路径均以当前会话项目为基准，也支持绝对路径和 `~`。不指定目录时，列表和检索覆盖整个全局知识库。文件列表使用单个 `parent_path`，并提供 `filename` 名称筛选，不区分大小写，支持部分名称。

示例：

```text
把 docs/ESP32开发手册.pdf 导入知识库。
在知识库中搜索开发板识别失败的排查方法。
只在 D:/资料/嵌入式 及其子目录搜索串口连接失败。
同时在 D:/资料/嵌入式 和 E:/项目/硬件 下搜索，引用来源路径和片段编号。
全局搜索固件烧录。
列出 D:/资料 目录中已经入库、文件名包含 ESP32 的文件。
```

## 文档解析与正文索引

正文向量通过 FastEmbed / ONNX Runtime 的 `BAAI/bge-small-zh-v1.5` 在本地生成，维度为 512。首次导入或搜索时下载模型到 `.xalling/xalling-embedding-models/`，之后可离线使用，文档不上传。导入时按正文片段生成向量；长片段按最多 400 字符分段嵌入，再归一化聚合。查询使用模型的 query 嵌入，正文使用 passage 嵌入。模型不可用时返回错误，不会将纯关键词结果标为混合结果。

Office、OpenDocument、RTF、EPUB、CSV、文字型 PDF 通过 AnyDoc 在本地转为 Markdown；TXT/Markdown 使用 UTF-8 读取。文件上限 200 MiB，解析后上限 2000 万字符。文本块最多 1400 字符，相邻块重叠约 200 字符，编号从 1 开始。扫描 PDF 需先在本地完成 OCR。

唯一的 Zvec 集合同时保存 Jieba / BM25 全文索引与 HNSW / Cosine 正文向量索引；文本块字段为 `text`、`source`、`mtime_ns`、`chunk_number`，向量字段为 `embedding`。新增、覆盖和删除均按规范化的 `source` 路径操作，不维护额外版本键。两路检索均按 `source` 限定目录范围。每路最多召回 `max(20, top_k * 4)` 个候选，通过 RRF（常数 60）融合，最终返回前 `top_k` 个片段。返回 `retrieval: "hybrid"` 和 `source`、`chunk_number`、`chunk_id`、`score`、`text`；`score` 是融合排名分数，不是置信度。正文只作为参考资料，不作为模型指令。

文件标识为规范化的绝对路径，清单以路径为键；Windows 上忽略路径大小写。每条记录保存 `source`、`mtime_ns`（文件修改时间，纳秒）、`chunk_count`。再次导入时先比较修改时间，相同则直接跳过，不读取或解析原文件；时间不同则重建该文件索引，包括时间变早的情况。不同路径分别入库，允许不同目录下的同名文件，不做内容去重。

`catalog.json` 是唯一依据，使用同目录临时文件写入、`flush` / `fsync` 后原子替换。清单写入失败时原有 JSON 保持完整。顶层 `pending` 保存待建索引的源路径：新增或更新记录时先加入，向量全部写入并刷盘成功后再移除。写入失败或中断时标记保留，下一次搜索直接重试；无需读取向量库判断是否写完。

`import_document()` 只判断文件是否更新，修改时间未变时直接返回 `unchanged`，不检查向量库。`search()` 先调用 `_sync()` 遍历 JSON：文件时间变化时更新；时间相同但仍在 `pending` 中时重试；时间相同且已完成时直接跳过，不读取或校验片段。整个索引目录丢失时按 JSON 重建。两者共用 `_write_document()` 执行“删除向量 → 原子更新 JSON 并标记待建 → 插入新向量 → 清除待建标记”。

每次正文搜索前先检查全库所有已入库文件的修改时间，包括当前搜索目录之外的文件。删除时先删向量，再原子更新 JSON；新增时先原子写入 JSON，再添加正文和向量。内容更新按同一 `source` 删除旧片段后重新添加。向量写入失败时保留已提交的 JSON，下一次查询据此重建，无需回滚或维护多版本。片段 ID 仅由路径和编号生成，修改时间只用于判断内容是否需要更新。文件移动后旧路径会移除，新路径需要另行导入。

文件修改后会在下一次正文搜索前自动更新，不进行后台监控；路径列表和目录树只展示当前清单，不触发同步。判断更新仅依赖修改时间：即使内容相同，只要修改时间变化也会重建；如果外部程序修改内容却保留修改时间，则会跳过，需先更新文件修改时间。未变化的文件只检查时间，不重读正文或重算向量。同步完成后才应用 `parent_paths` 范围并执行混合搜索。

## 存储与接口

```text
.xalling/
  xalling-knowledge/
    index/                # 全库唯一的正文集合
    catalog.json          # version 3，以文件路径为键，保存修改时间及块数
  xalling-embedding-models/ # 本地嵌入模型缓存
```

旧版清单和索引不自动迁移。version 2 索引缺少正文向量，需先备份并移走 `.xalling/xalling-knowledge/` 目录，再从原路径重新导入。只读 HTTP 接口为 `GET /api/knowledge/tree` 和 `GET /api/knowledge/documents`，均需认证。文件解析、向量计算和原生索引操作在线程中执行，通过进程内可重入锁保护正文存储，操作结束后关闭集合句柄。PyInstaller 收集 AnyDoc、Zvec、FastEmbed、ONNX Runtime 和 Tokenizers 的依赖，模型文件不进入安装包。
